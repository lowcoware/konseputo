## Method

1. Discovery via `gh search repos` with ~50 queries mixing: `topic:claude-skill`, `topic:claude-skills`, `topic:cursor-rules`/`cursorrules`, `topic:ai-agent-skills`, `topic:mcp-server`, `topic:claude-code` combined with `golang`/`python`/`rust`/`fastapi`/`api-design`, plus unquoted keyword combos (`spring boot skill`, `database schema skill`, `golang skill claude`, etc.) sorted by both `stars` and `updated`. ~1500 unique repos surfaced across all queries.
2. Deduplicated and filtered with a two-regex heuristic (skill/rule/agent-instruction signal AND backend-domain signal in name+description) down to ~550 candidates, then manually curated by reading descriptions for genuine backend-engineering relevance (excluded generic AI-agent harnesses, proxies, token-usage dashboards, memory systems, and unrelated consumer/data MCP wrappers that only incidentally mentioned "backend").
3. Downloaded via `git clone --depth 1`, then stripped `.git`, `node_modules`, `dist`, `build`, `.venv`, `venv`, `target`, `vendor`, `__pycache__`, `.next`, `.turbo` from every clone. No sparse-checkout was needed — all selected repos are already skill-repo-sized (no giant monorepos with skills buried in a subdirectory were selected).
4. Two repos hit Windows `MAX_PATH` limits (`peterbamuhigire/chwezi-dev-engine`, and one noname candidate) — resolved with `git -c core.longpaths=true clone`.
5. Several repos hit transient `Failed to connect to github.com:443` network errors during the batch and were retried individually until they succeeded.

## Notes / things skipped as irrelevant

Excluded from candidate pools despite matching search keywords (not genuine backend-engineering skill/rule content):
- Large generic AI-agent harnesses, CLIs, and proxies that only mention "backend" as their own implementation language (e.g. Rust-written agent runtimes, token-usage proxies/dashboards, multi-LLM routing gateways).
- Generic codebase-intelligence / knowledge-graph / memory-system tools (not backend-domain specific).
- Consumer-facing MCP wrappers around unrelated SaaS APIs (weather, job boards, WeChat, YouTube, etc.) that happened to use the word "backend" in their own description.
- Homework/bootcamp/portfolio SQL and Spring Boot student projects that surfaced under `database schema skill` / `spring boot skill` searches (these are not agent-skill repos, just learning projects).
- Duplicate forks of the same skill pack where the fork added nothing (kept the more complete/original one where identifiable).

## Rate-limit / operational issues encountered

- `gh` search (repos) is capped at 30 req/min and code-search at 10 req/min; both were hit during discovery and required a short backoff before continuing (observed via `gh api rate_limit`).
- Two `gh search repos` calls hit transient TLS connection resets (`connectex`/`wsarecv` errors) mid-run and were simply retried.
- During cloning, one interrupted background batch run left 2 repos (`wimolivier/postgresql-best-practices`, `SegfaultSorcerer/spring-grimoire`) in a partial state (directory existed, checkout incomplete) after a process was force-killed mid-clone; both were detected via a post-hoc empty-directory sweep and re-cloned cleanly from scratch.
- 3 candidate repos turned out to be genuinely empty upstream (`PHclaw/openclaw-skill-db-migration`, `zlaval/spring-claude-skills`, `kartiks-code/openapi-spec-designer` — GitHub API confirms "This repository is empty") and were dropped from the final noname list rather than left as empty placeholder folders.
- 5 individual clones hit transient `Failed to connect to github.com:443` mid-batch; all were retried individually and succeeded on the second attempt.

## Honest shortfall notes

- **top-stars: 50/50 delivered**, matching the target. This niche (backend-engineering-specific agent skills, as opposed to general-purpose AI-agent tooling) is genuinely thin at the high end of GitHub stars — the highest-starred genuinely-relevant repo (`samber/cc-skills-golang`) sits at ~2.8k stars, and the list tapers to double-digit-star repos by position ~30. Several very-high-star repos that surfaced in searches (100k+, 30k+ stars) were deliberately excluded as off-topic (science-agent skills, generic knowledge-graph tools, GitHub's own MCP server, etc.) rather than padding the count with irrelevant hits.
- **noname: 133/136 attempted survived** as real, non-empty repos (target was ~100, "up to however many genuinely qualify" — delivered above target). All are recently pushed (most within the last 90 days; a handful in the 90–150 day range where the repo was otherwise a strong, actively-maintained, low-star fit).
