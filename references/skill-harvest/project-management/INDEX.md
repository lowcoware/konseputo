## Method

- Search: `gh search repos` with `--topic claude-skill`, `--topic claude-skills`, `--topic agent-skills`, `--topic spec-driven-development`, `--topic adr`, `--topic architecture-decision-records`, plus free-text queries (`SKILL.md project management`, `SKILL.md ADR`, `SKILL.md sprint`, `SKILL.md backlog`, `SKILL.md changelog`, `SKILL.md retrospective`, `SKILL.md checkpoint`, `claude skill spec-driven`, `cursor rules adr`, `linear mcp skill`, `jira mcp agent skill`, `awesome-claude-skills`, `claude code project management skill`, `agentic project management`). Both `--sort stars` (top-stars) and `--sort updated --stars "<50"` (noname) variants were run.
- `gh search code` (for literal `SKILL.md` file-content search) was attempted but hit GitHub's code-search rate limit almost immediately (403, ~1 request before throttling) and was abandoned in favor of `gh search repos`, which has a much higher quota. This means the harvest is repo-metadata-driven, not code-content-verified: a small number of top-stars/noname entries may turn out not to contain an actual `SKILL.md` on inspection (e.g. IDE plugins, VS Code extensions, or CLIs that implement spec-driven/ADR workflows natively rather than as a Claude/Cursor-style skill file) — these were kept because they are still in-scope "agent-skill-format" PM tooling per the task's broad definition (Cursor rules / generic agent instruction repos / MCP PM tools all count).
- Candidates were deduplicated (1184 unique repos surfaced across 38 search result sets), then filtered to repos whose name+description matched a PM-relevance regex (spec-driven, ADR, sprint, backlog, changelog, retrospective, checkpoint, ticket tracking, project-management, scrum, kanban, task-master, PM, jira, linear, playbook, roadmap, traceability, governance, decision record) AND an agent/skill-context regex (skill, claude code, cursor, agent, mcp, codex, copilot, windsurf, gemini cli, openclaw, kiro) — 213 candidates passed both filters.
- Excluded as irrelevant: generic PM/kanban **software products** with no agent-skill framing (AppFlowy, Plane, OpenProject, Focalboard, Leantime, Kanboard, Vikunja, Huly, NocoBase, Worklenz, Tegon, PLANKA, Ever Gauzy, ERPNext, RT, dozens more) that only surfaced because they mention "project management" in their description; bug-bounty/pentest skills (src-hunter-skill, kali-pentest); pure design/presentation skills (ppt-agent-skill); SEO/spam-titled repos ("Best X Alternatives 2026", WordPress-plugin-bundle listings) that reused PM keywords for search-engine bait; and a long tail (~90 near-duplicate 0-star forks) of a single Udacity/course "agentic-project-management" (APM) homework template — only a representative handful of the most differentiated APM forks were kept in noname/ rather than harvesting every fork.
- **noname/ fell short of the ~100 target (85 delivered).** After the PM+skill relevance filter and the <50-star / pushed-within-~90-days window, only 85 genuinely distinct, non-duplicate candidates remained in the gathered search results. Padding further would have meant either lowering the relevance bar (letting in generic "AI project management SaaS" repos with no coding-agent skill content) or harvesting more of the near-duplicate APM course forks, both rejected as not meeting the spirit of the ask.
- Rate limits / connectivity: `gh search code` hit a 403 rate-limit almost immediately (see above). Several `git clone` / `gh search repos` calls hit transient `dial tcp` / TLS-handshake-timeout network errors mid-harvest (unrelated to GitHub rate limiting) — all were retried and succeeded on the next attempt; none caused a permanent gap in the dataset. Two clones (`Sushegaad/Claude-Skills-Governance-Risk-and-Compliance`, and a retry of the same) initially failed with a Windows `Filename too long` error from a deeply-nested path combined with the already-deep worktree path; fixed by re-cloning with `git -c core.longpaths=true` into a shorter local directory name (`012_Sushegaad-GRC-skills`).
- Leanness: `.git` was stripped from every clone (no history, no packfiles). No `node_modules`/`dist`/`build` cleanup pass was run beyond that — a few repos (notably `001_gsd-build-get-shit-done`, `012_Sushegaad-GRC-skills`) are large (tens of MB) because they ship bundled example outputs/eval artifacts alongside their skill files, not because of build output; total harvest size is ~662MB (top-stars) + ~801MB (noname) ≈ 1.46GB, larger than an ideal "skill files only" harvest would be. Given the volume (135 repos) a full per-repo sparse-checkout/raw-file-only pass was not performed under the time budget; if disk footprint matters, a follow-up pass could re-fetch only `SKILL.md`/`skills/`/`.cursor/rules/` paths per repo.
